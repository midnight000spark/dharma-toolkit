## Что я делаю

Отправляет одностороннее уведомление в Telegram через bash-скрипт
`scripts/notify.sh`. Скрипт читает токен и chat_id из
`~/.config/dharma/telegram` (вне репо).

## Когда меня вызывает агент (D-27)

Агент обязан уведомить пользователя в трёх точках:

1. **Завершение пакета** — после выполнения всех шагов пакета, перед финальным
   коммитом. Формат: `✅ <пакет>: <1 строка итога>, тесты N/N`.
2. **Стоп-гейт** — когда агент встаёт по правилу СТОП (конфликт, тесты
   красные после 3 итераций, обнаружена архитектурная проблема). Формат:
   `🛑 СТОП <пакет>: <причина>`.
3. **Ручная приёмка** — когда пакет требует ручного прогона сценария
   пользователем (как в 5.0.2). Формат: `👀 <пакет>: зелёный, прогони
   сценарий: <краткое описание сценария>`.

## Как использовать

Просто выполни bash-команду через shell-тул:

```bash
./scripts/notify.sh "✅ 5.0.2 завершён: B-3/B-4/B-11 закрыты, 64 теста зелёные"
```

## Правила сообщений

- Коротко: ≤200 символов. Пользователь получает пуш на телефон.
- Эмодзи в начале для быстрого сканирования (✅ / 🛑 / 👀).
- Без кода, путей, токенов, diff'ов.
- Без ссылок (Telegram может их не раскрывать).
- Markdown допустим для форматирования (`*жирный*`, `_курсив_`), но без
  блоков кода и вложений.

## Примеры

```bash
# Успех
./scripts/notify.sh "✅ 5.0.2: пресет работает, 64 теста"

# Стоп-гейт
./scripts/notify.sh "🛑 5.0.3: .watch() конфликтует с Riverpod, нужны инструкции"

# Ручная приёмка
./scripts/notify.sh "👀 5.0.2: flutter run -d linux, выбери Ньингма, проверь счёт"
```

## Безопасность

- Токен в `~/.config/dharma/telegram` (права 600, вне git).
- Скрипт fail-silent: при любой ошибке exit 0, пакет агента не падает.
- Никогда не логируй содержимое сообщения, если оно может содержать
  чувствительные данные (по умолчанию все сообщения — статусные, но
  перестрахуйся).

## Если конфиг отсутствует

Скрипт молча завершается — это не ошибка. Пользователь может работать
без уведомлений; агент не должен требовать их наличия.
