# Математическая модель календаря: спецификация

> 4 традиции: **Пхугпа**, **Цурпху (Цурлуг)**, **Шен Бон (Юнгдрунг Бон)**, **Тхеравада**
> Статус: рабочий документ (draft). Версия: 1.0. Дата: 2026-09-24.
> Мобильное приложение: Flutter, `lib/features/calendar`.

---

## 0. Архитектура

```
┌────────────────────────────────────────────────────────────┐
│ Слой подсветки (оверлей, коллизии, приоритеты, таймзоны)   │
├────────────────────────────────────────────────────────────┤
│ Слой праздников (словарь лунных дат по традиции, правила    │
│   наблюдения на пропущенных/удвоенных днях)                │
├────────────────────────────────────────────────────────────┤
│ Движок A: Kālacakra (сиддханта/карана)                     │
│    варианты: Пхугпа · Цурпху · (Бон-кандидаты)             │
├────────────────────────────────────────────────────────────┤
│ Движок B: Юго-Восточная Азия (лунно-солнечный)             │
│    варианты: Тайский (Suriyayatra) · Мьянма (Thandeikta)    │
│    · Шри-Ланка (Poya) + солнеч. события (Сонгкран)         │
├────────────────────────────────────────────────────────────┤
│ Ядро: Григориан ↔ Юлианский день ↔ лунные даты             │
└────────────────────────────────────────────────────────────┘
```

Правила построения:

- **E1.** Две независимые системы представления: движок A (тибетская Кālacakra-семья) и
  движок B (Юго-Восточная Азия/Тхеравада). Они не конвертируются друг в друга напрямую —
  связь только через гражданскую дату (проекция на григорианский день).
- **E2.** Каждая традиция = набор параметров для движка + свой словарь праздников.
  Параметры версионируются и содержат ссылку на источник.
- **E3.** Гражданский тип «суток» (начало дня) — параметр традиции (см. §7, W6):
  - Тибетские (Пхугпа/Цурпху/Бон): **от рассвета до рассвета**.
  - Тай: помоздний — конфигурируемая (по умолчанию полночь).
  - Мьянма: традиционный утсатха от рассвета до рассвета, конфигурируема.
  - Шри-Ланка: Poya по официальной газете (локален полнолуний).
- **E4.** Все расчёты на BigInt/длинная арифметика, без float-сравнений на границах
  (см. подход порта vajradog/TCG).
- **E5.** Детерминизм: одинаковый вход → одинаковый выход на любой платформе.

## 1. Общий движок A (Kālacakra)

Правила, общие для всех тибетских вариантов (эталон — TCG Э. Хеннинга,
`kalacakra.org/calendar/`, MIT; реализовано в `phugpa_port.py`).

**R1. Единицы.** Долготы — в 27 созвездиях (rgyu skar) по 13⅓°, далее 60 nāḍī,
60 pala, 6 вдохов (dbugs). Смешанно-основанные числа записываются как
`3;10,49,2,347(707)`. Время — счёт неполных солнечных дней по 7-дневной неделе (сб=0).

**R2. Три типа «дня»:**
- `khyim-zhag` — зодиакальный день (1/30 солнечного месяца);
- `tshes-zhag` — титхи, лунный день = 12° элонгации Луны от Солнца;
- `nyin-zhag` — гражданский день от рассвета до рассвета.

**R3. Ключевые константы сиддханты (общие для Пхугпа и Цурпху):**
- 67 лунных месяцев = 65 солнечных → среднее движение Солнца за месяц
  `2;10,58,1,17 (67)`; карана-вариант `2;10,58,2,10 (13)`.
- 11312 лунных дней = 11135 солнечных → среднее приращение дня недели
  `1;31,50,0,480 (707)`; карана: 10800/10361.

**R4. Интеркаляция (високосный месяц).**
Интеркаляционный индекс `zla-dag` = «истинный месяц» от эпохи. Когда дробная часть
переносится через целочисленный порог (`M×1;2 + конст.`), месяц високосный
(Солнце не переходит знак). По современной тибетской практике повторяется
**следующий** месяц; задержанный месяц — `zla bshol` (два месяца с одним номером).

**R5. Удвоения/пропуски титхи.**
Гражданский месяц = 29–30 дней; титхи считаются 1–30. Если конец титхи `gza-dag`
выпадает «поздно вечером перед рассветом» — титхи повторяется (`lhag` — дубль, один
номер дважды), если «рано утром» — титхи пропускается (`chad`). Не-титхи-дни сами
никогда не пропускаются и не дублируются.

**R6. Счёт дней.** `general day` = число солнечных суток с эпохи (JD на 12:00 GMT).
Лунный день привязан ко времени окончания титхи; расчёт на долготу = 91° (Лхаса).

**R7. Структура месяца.** Месяц начинается с дня, в котором заканчивается титхи №1.
Названия месяцев — «Hor-порядковый» счёт: 1-й Hor месяц, … Год альманаха начинаетcj
с 3-го Hor месяца. Классические имена (для словаря):
`1=mchu, 2=dbo, 3=nag, 4=sa-ga, 5=snron, 6=chu-stod, 7=gro-bzhin, 8=khrums,
9=tha-skar, 10=smin-drug, 11=mgo, 12=rgyal`.

**R8. Параметры системы** (`struct KalacakraParams`):
`epoch_jd`, коэффициенты и константы `true_month / mean_weekday / anomaly / mean_sun`,
метод Солнца (siddhānta/karaṇa), правило интеркаляции (индекс 46–49), долгота для дня.

## 2. Пхугпа (tradition=phugpa)

**Правила расчёта:**
- Сиддханта `grub rtsis` для Солнца и Луны. Накопленная ошибка долготы Солнца ~ −36°
  (расхождения с реальной астрономией до месяца) — **не** влияет на структуру
  календаря: важим средний сдвиг недели и титхи.
- Эпохи (эквивалентны, выводимы из обобщённой −1000):
  - **1687 «Байдурья»** (Sde srid Sangs rgyas rgya mtsho);
  - **1681 Smin-gling** (Smin gling lo chen): epoch JD 2335140; general day 5121;
  - **1927 «Сущность Калки»** (Mkhyen rab nor bu).
  - Рабочая: `Generalised Phugpa, epoch −1000`.
- Параметры (mean/приращение):
  - True month: `M×1;2 + конст. (1,65)`;
  - Mean weekday: `M×1;31,50,0,480 + конст. (707)`;
  - Mean Sun: `M×2;10,58,1,17 + конст. (67)`;
  - Anomaly: `M×2;1 + конст. (28,126)`.

**Праздники (словарь лунных дат):**
Losar = 1 д. 1 мес; Сага Дава 15 д. 4 мес (паринирвана Будды); День подношения 1 д.
12 мес; Сачен Кунга Ньингпо 14 д. 9 мес; Лонгченпа рожд. 8 д. 2 мес, паринирвана
18 д. 12 мес; Джигме Лингпа паринирвана 3 д. 10 мес; Гуру Ринпоче рожд. 10 д. 5 мес.
Правило «месяц-12 → гражданский год события».

**Критерии:**
- **K1.** Losar за 1900–2100 совпадает с альманахом Men-Tsee-Khang (Дхарамсала) — допуск 0 дней.
- **K2.** Тест-векторы: Losar 2151=10.02.2024, 2152=28.02.2025, 2153=18.02.2026, 2154=07.02.2027.
- **K3.** Карта титхи (удвоён/пропущен/обычный день) для 2000–2030 совпадает с официальным
  альманахом — допуск 0 по статусу каждого дня.
- **K4.** Регрессия событий: Сачен 14 м9 → tib 2151 m9 d14 = 14.11.2024; рождение
  Лонгченпы 8 д. 2 мес; паринирвана 18 д. 12 мес (сверка с rywiki).
- **K5.** Обратное преобразование (Григориан→tib→Григориан) биективно в пределах года.

## 3. Цурпху / Цурлуг (tradition=tsurphu)

**Правила (по TCG и публикациям Rumtek):**
- Школа Карма Кагью; система `mtshur lugs` начата 3-м Кармапой Рангджунгом Дордже
  (кон. 13 в.), окончательно оформлена Джамьянгом Дондупом Вёзером (**1447**).
- Главное отличие от Пхугпа: долгота Солнца считается по **карана (byed rtsis)**
  (из Калачакра-тантры), а не по сиддханте (сейчас точнее: ошибка −24,2° против
  −31,0°). **На структуру дней/интеркаляцию не влияет** — те же титхи дублируются/
  пропускаются, те же високосные месяцы.
- Високосный месяц определяется по **сиддханта-индексу** (не по карана), как в реальных
  изданных календарях Румптека.
- Эпохи Цурпху (любая, выводима из обобщённой −1000):
  - **1732** (Karma Ngelek Tendzin);
  - **1824** (14-й Кармапа Thegchog Dorje);
  - **1852** (Джамгон Конгтрул, «Сжатый компендиум») — по умолчанию;
  - `Combined siddhānta & karaṇa` (byed grub zung 'grel, 1852) — экспериментальный вариант;
  - **1987 Sherab Ling** (Tai Situ, полуреформированный, эпоха JD 2446884; точное
    Солнце `2;10,58,2,564,5546 + 25;41,58,2,25,6655 (707,6811)`) — опциональный профиль.
- Параметры:
  - Mean weekday: `M×1;31,50,0,8,584 + конст. (13,707)` ≡ `M×1;31,50,0,480 + конст. (707)`;
  - Mean Sun: `M×2;10,58,1,3,20 ± конст. (13,67)` (≡ сиддханта-вид; карана — отдельно, tcgbk).

**Критерии:**
- **T1.** Лосар и все дубли/пропуски дней совпадают с изданным календарём Rumtek
  (или KIBI) за 2000–2030 — допуск 0.
- **T2.** Свойство связи с Пхугпа: в большинство лет идентичен, изредка ±1 день.
  Зафиксировать: Цурпху-2026 = Пхугпа-2026; 2027 различаются (дублированный
  1-й месяц у Пхугпа 2154).
- **T3.** На исключениях: месяц с дублированным 1-м месяцем (tib 2154) — корректная
  расстановка `zla bshol`.

## 4. Шен Бон (Юнгдрунг Бон) (tradition=shenbon)

Статус: открытого алгоритма Бон-календаря нет в открытых исходниках; зафиксировано
«Бон ≈ Хорда» (счёт «hor»/монгольский). Модель строится как отдельный слой поверх
движка A с процедурой извлечения параметров.

**Правила:**
- **B1.** Год/месяцы — «Hor-порядковый» счёт; старотибетские особенности отсчёта
  (до-калачакра); день — от рассвета.
- **B2.** Свои эпохи не публикуются. Гипотеза: Бон = вариант старого счёта (`nag rtsis`).
  Не смешивать с Пхугпа: **Лосар Бон может отличаться до ±1 месяца**.
- **B3.** Интеркаляция и дубли/пропуски — эмпирически (см. B6); равенство Пхугпа не
  гарантируется.
- **B4.** Фестивальный словарь Бон: Тонпа Шенраб (рождение/паринирвана), Шенлха Окар,
  годовщины линии, менри-новый год. Лунные даты сверять по юбилейным годам и местным
  монастырским альманахам.
- **B5.** Все даты — «лунная дата → гражданский день» по Бон-варианту; сводка с
  Пхугпа — оверлей.
- **B6. Процедура калибровки.** Собрать 30+ лет официальных календарей
  Menri/Triten Norbutse (1960–2030): разметить (a) титхи на каждый гражданский день,
  (b) високосные месяцы, (c) Лосар. Подобрать epoch+константы к движку A, чтобы:
  по датам Лосар — 0 расхождений; по карте титхи — <1% дней. Если подгонка не
  сходится — табличный слой («год → дата Лосар», «год → карта дней») без полного вывода.

**Критерии:**
- **B1.** Лосар 1980–2030 совпадает с опубликованным календарём Menri (допуск 0).
- **B2.** ≥90% дней карты титхи совпадают в тестовом окне (эталон = Menri; Бон-школы
  допускают локальные вариации центров).
- **B3.** У каждого фестиваля в БД правило наблюдения на пропущенном/удвоенном дне
  (по практике Бон).
- **B4.** Расхождения выводить на экран только по факту: «Бон vs Пхугпа: лосар сдвинут на X».

## 5. Тхеравада (движок B)

Не Калачакра. Два подмодуля: (i) лунно-солнечный календарь региона; (ii) солнечные события.

**Общие правила:**
- **V1.** Гражданская дата — григорианская; месяц привязан к фазам Луны. Сводные сигналы:
  «8/15 восходящей», «8/15 нисходящей», «полнолуние», «новолуние».
- **V2.** Праздники: Магха Пуджа (полнолуние 3 мес), Вишакха (полнолуние 6 мес),
  Асальха (полнолуние 8 мес), начало/конец Вассы, Паварана, Катхина, Сонгкран/Тхингян.
- **V3.** Упосатха: 8-е и 15-е растущей, 8-е и 15-е убывающей (либо 14-е в короткий месяц).

### 5.1 Тайский (Thailand)
- Эры: BE = CE + 543, Чуласакарат CS = BE − 1181; месяцы — лунно-солнечный Suriyayatra.
- Интеркаляция (аналог метонова цикла): 7 високосных месяцев на 19 лет (adhikamāsa)
  + 9 adhikavāra (високосный день в 7-м месяце) в цикле.
- Сутки `wan phra`: полночь (конфигурируемо).
- Эталон: официальный буддистский календарь / объявляемые «Wan Phra».

### 5.2 Мьянма (Myanmar)
- Эра: ME = CE − 638 (после Tagu); ME 2026 ≈ 1388.
- Месяцы: Tagu…Tabaung (12 лунных + високосный Waso).
- Система **Thandeikta**: високосный Waso по табличному циклу (не метонов цикл!),
  редкий високосный день (Nayon leap day).
- Сутки для утсатха: 6:00 / рассвет (конфигурируемо).
- Эталон: печатный мьянмский календарь / релиз Министерства по делам религии.

### 5.3 Шри-Ланка (Poya)
- Нет собственного лунного счисления: Poya = каждый официальный полнолунник из
  правительственной газеты (годовой список).
- Vesak/Poson/Esala/Il Poya — по названиям сингальских месяцев.
- Модель: полнолуния движка B + **локальная таблица «год → даты Poya»** (обновление
  1×/год); внутренний расчёт не должен отличаться от газеты более чем 0 дней.

### 5.4 Солнечные события
- **V5.** Сонгкран/Тхингян: момент, когда тропическая долгота Солнца = 0° Овна
  (≈13–15 апреля). Солнечная модель VSOP87 низкой точности (±1 день), затем точная
  привязка к дате. Это **тропическое** значение (в отличие от тибетского сидерического
  счёта).

### Критерии движка B
- **V1.** Полнолуния/новолуния 2000–2030 совпадают с региональными альманахами
  (допуск 0 по дате; при меридианной разнице — задокументированные ±1 день и правило
  «доверяем региональному»).
- **V2.** Сонгкран: дата 2000–2030 — допуск 0.
- **V3.** Упосатха-карта = эталон региона, 0.

## 6. Слой праздников и подсветки

- **P-1.** У каждого лунного события «правило наблюдения»: пропущенный день —
  перенос по практике конкретной школы (конфиг); удвоенный — приоритет «основного»
  дня (main); при расхождении традиций — правило своей традиции.
- **P-2.** Оверлей: одна гражданская дата может быть праздником в нескольких
  традициях. Приоритет: выбранная пользователем традиция → общие события (Losar/
  Visakha совпали) → прочие. Даты, где традиции расходятся, попадают в список
  «расхождения» и подсвечиваются.
- **P-3.** Правила расхождений месяцев: «месяц-12 → гражданский год события»
  (тибетское); «високосный месяц → два месяца с одним номером (zla bshol)» — спецметки.
- **P-4.** Словарь фестивалей: `lunar_date + observance_rule + per_school_flag`;
  каждое правило с source-ссылкой в комментарии.

## 7. Сквозные критерии (все модели)

- **W1. Детерминизм/воспроизводимость:** одинаковый вход → одинаковый выход на любой
  платформе (BigInt, без float-сравнений на границах).
- **W2. Golden-тесты:** файлы-эталоны по каждой традиции (минимум 2000–2030, желательно
  1900–2100), генерируются из официальных альманахов; CI-прогон.
- **W3. Граничные кейсы:** годы с високосным месяцем; год с дублированным 1-м месяцем
  (2154); пропуск 30-го титхи; «месяц-12 → февраль следующего года»; переход через
  Losar/Сонгкран.
- **W4. Производительность (мобильные):** прекомпиляция сетки 1–2 года офлайн,
  кэш готовых дней; расчёт месяца <10 мс.
- **W5. Локализация/a11y:** названия месяцев и праздников: тибетский/английский/русский;
  все праздники — с пояснением.
- **W6. Таймзона:** тип суток и заякоривающий меридиан — параметр традиции
  (Лхаса 91° / Бангкок / Янгон / Коломбо); счёт всегда в фиксированном локальном
  времени региона, отображение — в таймзоне устройства.
- **W7. Подсветка:** только по факту события; расхождения традиций отдельным маркером.
