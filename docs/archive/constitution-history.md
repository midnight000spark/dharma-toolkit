# AGENT — архив: история конституции (read-only)

> Перенесено verbatim из `AGENT.md` при разгрузке документации (D-38, пакет `docs-arch-1`).

## История конституции
- **v1** (2026-08-26): исходная — миссия, три принципа модульности, стек,
  структура, Tier-0, правила кода, схема классификации.
- **v2** (2026-09-01, по итогам аудита `docs/REVIEW-2026-08-31.md`):
  - добавлена иерархия документов и правило «код — источник истины о факте» (R-17);
  - D-20: агрегация схемы БД в ядре как единственное ослабление принципа №1;
  - D-4 усилен D-22: service locator запрещён явно, DI только через Riverpod;
  - D-21: EventBus отложен до реального потребителя;
  - D-17: регламент миграций поднят в конституцию;
  - добавлены правила приёмки (уроки аудита 1–4);
  - добавлена модельная стратегия D-19;
- стек приведён в соответствие с pubspec.yaml (mocktail убран из «подтверждённого»,
  добавлена локали zация ru).
- **v2.1** (2026-09-01, D-27): добавлен скилл telegram-notify для односторонних
  уведомлений о статусе пакетов; fail-silent, токен вне репо.
- **v2.2** (2026-09-01): добавлена секция «Вход в курс (свежая сессия)» —
  постоянный порядок восстановления контекста и базовая линия до первой правки.
- **v2.3** (2026-09-01, инцидент F-37): в модельной стратегии — правило самоотчёта
  модели в начале каждой сессии; `.opencode/agent/dharma.md` исправлен
  (qwen3.7-plus → qwen3.8-flash, variant high) и синхронизирован с конституцией v2.2.
- **v2.4** (2026-09-01, F-39): модельная стратегия приведена к реальному меню
  variant'ов (Default/low/medium/xhigh; high/max у qwen3.8-flash нет, невалидное
  значение молча даёт Default); в правилах приёмки — урок 5 (урок F-38:
  гонки/атомарность детерминируются на уровне репозитория, виджет-тесты — UX).
- **v2.5** (2026-09-01, 5.0.6/R-17): в стеке mocktail переведён из «подтверждённого»
  в явное «не подключён» (в pubspec.yaml его нет, моков нет — расхождение документа
  с кодом устранено; версия v2.4 к тому моменту уже занята правкой F-39).
- **v2.6** (2026-09-01, 5b блок 0, R-17): указатель на БФТ исправлен с устаревшего
  `docs/BFT-v1.1.md` на актуальный `docs/BFT-v1.4.md` с правилом «актуальная версия —
  файл с наибольшим номером» (конвенция версионирования БФТ файлами роняла указатели —
  то же предупреждение продублировано в CONTEXT.md и `.opencode/agent/dharma.md`).
- **v2.7** (2026-09-01, sync-docs-5b): указатель на БФТ обновлён v1.4 → v1.5
  (FR-CAL-1/2 синхронизированы с кодом 5b.1/5b.2; §13 БФТ объявлен срезом при
  реестре STATE.md — устранён второй источник истины по багам/рискам); CONTEXT.md
  и `.opencode/agent/dharma.md` синхронизированы.
- **v2.8** (2026-09-01, пакет A по решению пользователя): процессные правила —
  (1) **гигиена кластера** в «Запрещено»: новых упоминаний кластера в коде/комментариях/
  docs/payload не вводить, существующие не чиститься (страховка R-18; H-4 опровергнута
  зондами 15/15, но перестраховка дешевле мёртвых сессий); (2) и (3) секция
  «Свежесть документов» в правилах приёмки: TODO со ссылкой на закрытый этап = баг
  документа; README сверяется после тегирования `stage-*`.
- **v2.9** (2026-09-01, пакет A-resume): самопроверка пакета A выявила, что правило
  гигиены (введено в v2.8) было записано прямыми упоминаниями кластера — строки
  переформулированы только косвенными ссылками новым коммитом (граница «не чистить
  существующие» относится к упоминаниям старше пакета A); «Модельная стратегия»
  дополнена правилом свежих сессий (урок обрыва #12, R-18). *Строка истории заведена
  постфактум в v2.11: правка была в репозитории, записи в этом списке не было;
  дублирующая строка без пометки удалена в v2.12 (баг документа, R-17).*
- **v2.10** (2026-09-01, 5b.5): указатель на БФТ обновлён v1.5 → v1.6 (файл-на-версию);
  *строка истории также постфактум*.
- **v2.11** (2026-09-01, CI-наведение порядка): в правилах приёмки — секция «Зелёный CI —
  тоже проверяемое утверждение» (D-33, R-25): статус подтверждается командой
  `./scripts/ci_status.sh` (анонимный публичный API, exit 0/1, `--steps`), при недоступности
  — ⏳ с причиной вместо ✅. Причина — F-53: ключ `gh` в keyring невалиден после отзыва PAT
  (F-41), и «CI зелёный» мог повиснуть как непроверяемое утверждение.
- **v2.12** (2026-09-01, пакет 5b.6): процессные правила приёмки — (1) **политика TODO**
  в «Свежести документов»: отложенное намерение живёт в STATE/ROADMAP с номером,
  а не в виде TODO в коде; удаление TODO без переноса намерения = баг документа;
  (2) **теги контрольных точек**: сабпакет → `stage-X.Y` по завершении, тег этапа
  `stage-X` — только в конце после ручной приёмки (урок «выбившихся тегов»);
  (3) новая секция **«Гигиена скриптов, правящих файлы»** — чтение в память до
  открытия на запись (урок инцидента 5b.3-resume: скрипт мутации затёр lib-файл).
  Попутно удалена дублирующая строка истории v2.9 (баг документа, R-17). Позже в тот
  же пакет усилена «Модельная стратегия»: финальный отчёт — короткое резюме
  (урок обрыва #16, F-54).
