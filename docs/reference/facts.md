### F-39: варианты Qwen3.8 Flash в OpenCode — Default/low/medium/xhigh; «high» был невалидным пином
- **Описание**: реальное меню variant'ов модели в TUI: Default, low, medium, xhigh. Схема opencode (`opencode.ai/config.json`) определяет `variant` как свободную строку без enum — невалидное значение не роняет старт и молча даёт поведение по умолчанию. Для Qwen3.8 Flash high/max не существуют; Default = серверный xhigh по доке Qwen (максимальная глубина). Пин `variant: high` из пакета F-37 был невалидным — сессии фактически шли на умолчании (xhigh), что и наблюдалось в самоотчётах. low на агентных задачах даёт ретраи и суммарно дороже (дока Qвена) — не используется. Итог: dharma.md → `variant: xhigh` (эквивалентен Default, но самодокументируем), формулировки глубины — по реальному меню.
- **Источник**: наблюдение пользователя (меню TUI), `opencode.ai/config.json` (curl, 2026-09-01), дока Qwen через оркестратора
- **Дата**: 2026-09-01

### F-57: платформенные ограничения планирования уведомлений (iOS 64 / Android exact+boot / Linux без планировщика)
- **Описание**:
  - **iOS**: держит только **64 последних** pending-уведомления, 65-е отбрасываются
    молча (на iOS 9 и старее — 64 ближайших по времени). Горизонт планирования
    обязан давать pending ≤ 64 — для MVP с запасом: 60 дней × ≤1/day + паки.
  - **Android 13+ (API 33+)**: показ требует runtime **POST_NOTIFICATIONS**
    (запрос через AndroidFlutterLocalNotificationsPlugin.requestNotificationsPermission).

    разрешении exact-планирование **не выполняется** (лог-ошибка) — fallback обязателен

    после перезагрузки. OEM-фоновые ограничения — остаточный риск.

    ( freedesktop Desktop Notifications / DBus, flutter_local_notifications_linux

    `zonedSchedule`/`pendingNotificationRequests`/`cancel` — базовый интерфейс бросает

### F-59: порт календаря расширен до `SpecialDaysSource` (D-37 + D-35, пакет 6.1 блок C)

### F-60: механизм объективной остановки по стоимости сессии OpenCode (пакет `infra-cost-guard`)
- **Описание**: агент изнутри сессии видит стоимость неточно (прецедент: отчёт заявил
  ~$0.45 при фактических $0.71), поэтому триггер остановки по лимиту снят с самооценки
  модели и поставлен на объективный счётчик из трёх частей:
  1. **Визуальный контроль** — TUI-плагин `token-tracker`
     (`~/.config/opencode/plugins/token-tracker.tsx`, upstream
     `eserete/opencode-token-tracker`, sha256 `a1d56f6d…`). Это **TUI**-модуль: он
     подхватывается не серверным загрузчиком, а регистрацией в
     `~/.config/opencode/tui.json` (`"plugin": ["./plugins/token-tracker.tsx"]`);
     футер сайдбара показывает `last`/`total` по токенам, числу запросов и цене.
     Загрузка модуля подтверждена маркером на старте TUI (события загрузки в лог не
     пишутся — прямая проверка «модуль вычислен» надёжнее «нет ошибки»).
  2. **Жёсткая остановка** — `.opencode/plugins/budget-guard.ts`: слушает `event` →
     `message.updated` (`properties.info.cost` у assistant-сообщений) и
     `session.updated`, накапливает стоимость монотонно (повторные апдейты одного
     сообщения не двоят счёт), перед каждым инструментом сверяется с бюджетом и
     **бросает ошибку** из `tool.execute.before` при `cost >= budget`. Бюджет —
     `OPENCODE_BUDGET_USD` (default 0.5; env-переопределение вместо правки константы,
     чтобы тестовое значение не осталось в коде), журнал — `OPENCODE_BUDGET_LOG`.
     Дополнительно (не чаще раза в 5 с на сессию) читает авторитетную `session.cost`
     из SQLite; при недоступности `sqlite3` тихо деградирует на событийный счётчик.
  3. **Fallback** — `scripts/cost-check.sh`: последние N сессий с ценой, токенами и
     провайдером прямо из `session.cost` / `json_extract(model,…)` в
     `~/.local/share/opencode/opencode.db`.
- **Ограничение загрузчика (важно)**: OpenCode 1.18 сканирует `{plugin,plugins}/*.{ts,js}`
  **нерекурсивно** и требует, чтобы **каждый** экспорт файла-плагина был плагином
  (функция или `{ server }`); посторонний экспорт (константа, утилита) роняет загрузку
  с `Plugin export is not a function`. Поэтому `budget-guard.ts` экспортирует ровно один
  `default { id, server }`, а поведение проверяется через хуки, а не через внутренние
  функции. Подпапки внутри `plugins/` загрузчик не сканирует, но файлы-спутники туда
  всё равно не кладутся.
- **Доказательство**: `bun test scripts/budget_guard_test.ts` — 14 тестов на настоящем
  плагине (дедупликация, порог и равенство, изоляция сессий, деградация при отказе БД,
  кэш сверки); мутации M1…M7 (в т. ч. снятие гарда на `Infinity`) красные,
  восстановленный файл зелёный. Живой прогон в изолированном каталоге: бюджет
  `$0.000001` — первая команда прошла, вторая **заблокирована** с ошибкой бюджета и
  записью в журнал; на дефолтном `$0.5` обе команды прошли (ложных срабатываний нет).
  Авторитетный SQLite-путь подтверждён на реальной базе (`session.cost` вложенной сессии).
- **Источник**: пакет `infra-cost-guard` (коммиты `5338ff9`, `9e023cf`, `751ef5a`),
  документация OpenCode (plugins), отчёт big-pickle 2026-09-15
- **Дата**: 2026-09-15
